# Справка по `$fpf`

`$fpf` — один навык с графом лениво загружаемых промптов. Передайте ему прямую команду или задачу на русском либо английском языке. Канонические имена команд остаются английскими; русские псевдонимы поддерживаются маршрутизатором.

## Дерево команд

```text
$fpf
├── help                  показать эту страницу; никогда не сохраняет отчёт
├── plan                  вернуть только план вызовов; не исполняет и не сохраняет
├── applicability scan    найти релевантные паттерны FPF
├── sota harvest           построить ограниченную карту актуальных данных
├── options explore        сгенерировать и сравнить альтернативы
├── design challenge       критически проверить предложение до реализации
├── decision synthesize    выбрать из оценённых альтернатив и оформить ADR
├── quality improve        изменить и повторно оценить версионированную цель
└── alignment audit        проверить реализованную или принятую работу
```

Семь аналитических команд возвращают полный результат в чате и по умолчанию сохраняют один отчёт. `$fpf help` и `$fpf plan` отчёты не сохраняют.

Прямые аналитические команды: `$fpf applicability scan`, `$fpf sota harvest`, `$fpf options explore`, `$fpf design challenge`, `$fpf decision synthesize`, `$fpf quality improve` и `$fpf alignment audit`.

## Объединение аналитических команд

Для одного явного последовательного запуска используйте ` + ` с пробелами:

`$fpf design challenge + quality improve + alignment audit Усиль это версионированное предложение.`

Общую задачу указывайте только после последней команды. Каждая соседняя пара должна быть разрешённым переходом графа. Запуск использует одну кампанию, единый реестр находок и один итоговый отчёт. При нехватке данных, решения или полномочий на изменение он останавливается, не выдумывая разрешение и не перезапуская проверку по кругу.

Итоговый артефакт содержит один дедуплицированный список всех проблем и слабых мест в заявленных границах и профиле оценки, а также один упорядоченный список исправлений и улучшений с привязкой к находкам. Промежуточные команды не сохраняют отдельные отчёты.

## Примеры

- `$fpf помощь`
- `$fpf планировщик Нужны актуальные исследования, варианты и решение владельца.`
- `$fpf проверка дизайна Проверь эту модель области до реализации.`
- `$fpf проверка дизайна + улучшить качество Усиль это версионированное предложение.`
- `$fpf проверка дизайна + улучшить качество + аудит согласованности Исправь и проверь это предложение.`
- `$fpf аудит согласованности Проверь принятые исправления по зарегистрированным находкам.`
- `$fpf Какие паттерны FPF применимы к этому ограниченному вопросу о дизайне сервиса?`

Используйте `$fpf plan`, когда нужен только рабочий процесс без исполнения аналитических промптов. Для прямой команды текст после неё становится задачей выбранного промпта. В композиции задача указывается только после последней команды.

## Язык результата

`output_language = "auto"` выбирает русский, если вызов или оставшаяся задача содержат осмысленный русский текст на кириллице; иначе выбирается английский. Значения `ru` и `en` фиксируют язык. Явная инструкция пользователя имеет приоритет над доступной настройкой проекта, а настройка — над встроенным значением. Точные команды, идентификаторы FPF, пути, код, цитаты и ссылки не переводятся.

## Режимы отчёта

По умолчанию аналитические команды используют `save_report = "on"` и `report_style = "plain"`. Доступный `.caprmedio/settings.toml` может выбрать `report_style = "caprmedio"`; явная инструкция пользователя имеет приоритет. Режим CAPRMEDIO создаёт ненормативный Analysis Report Atom в самом узком доказанном Scope Unit, содержащем весь охват анализа. Если топологию или правила допуска Atom нельзя надёжно определить, сохранение прекращается без догадок.

Канонический синтаксис Codex — `$fpf`. Маршрутизатор также понимает текстовый префикс `/fpf` для переносимости между хостами, но это не регистрирует отдельную slash-команду.
