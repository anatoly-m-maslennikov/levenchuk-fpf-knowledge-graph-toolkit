# Справка `$fpf` — Разработка ПО

Используйте эту область для DDD и ограниченных контекстов, бизнес-логики, требований и приёмки, TDD, качества кода, архитектуры ПО, интерфейсов и миграций, а также доказательств готовности к выпуску.

## Типичные профили

- DDD и ограниченные контексты
- Бизнес-логика и поведение предметной области
- Требования и приёмка
- Разработка через тестирование
- Качество кода
- Архитектура ПО
- Интерфейсы, зависимости и миграции
- Доказательства и гейты выпуска

## Типичные вызовы

- `$fpf рамка проблемы Сформулируй проблему функции, требования и границу приёмки.`
- `$fpf восстановить структуру Построй карту текущих ограниченных контекстов и бизнес-правил.`
- `$fpf исследовать варианты Сравни кандидаты архитектуры ПО без выбора победителя.`
- `$fpf дизайн оценки Определи стратегию тестирования TDD или оценку качества кода.`
- `$fpf проверка дизайна Проверь предлагаемую миграцию API до реализации.`
- `$fpf улучшение качества Улучши версионированный модуль и повтори оценку.`
- `$fpf аудит согласованности Проверь реализацию по принятой архитектуре и проверкам выпуска.`

Профиль определяет предмет, а команда — аналитическое намерение. Слова «DDD», «TDD» или «архитектура» сами по себе не выбирают между восстановлением, проектированием, улучшением и аудитом.
