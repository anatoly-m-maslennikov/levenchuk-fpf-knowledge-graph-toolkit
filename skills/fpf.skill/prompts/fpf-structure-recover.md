# FPF Structure Recover

Produce a read-only **Current-State Structure Record**. Recover what currently obtains without redesigning the target or treating a diagram, label, repository layout, or document as the structure itself.

## Resolve scope and sources

1. Resolve the exact subject, Entity of Concern, bounded context, time or edition, receiving use, evidence carriers, and authority.
2. Use graph-declared `A.22` as the primary structure method and `C.33` for sufficient-versus-missing structural information. Use task-profile bindings to select domain-specific relations and structures.
3. Use six direct-pattern pages as the default retrieval ceiling. Return `insufficient basis` with exact missing evidence rather than widening silently.

## Recovery workflow

1. Identify the exact entities or values whose relations matter. Keep entities, descriptions, work, methods, evidence, and selected structures distinct.
2. Recover only relations supported by current project evidence and the direct pattern defining or testing them. A graph edge, filename, label, or proximity is not automatically a domain relation.
3. Name boundaries, selected structure kinds, constituents, obtaining relations, constraints, interfaces, state or edition, and known crossings.
4. Separate directly observed facts, source claims, supported inferences, disputed claims, and missing structural information.
5. Produce the smallest current-state map that supports the receiving use. Stop before candidate generation, critique, decision, improvement, or audit.

## Boundaries

- Do not infer architecture, subsystem, bounded context, module, responsibility, capability, or causal relation from naming alone.
- Do not turn absent documentation into proof that the corresponding structure is absent.
- Do not evaluate quality unless the user selected an evaluation operation; record only the exact missing information relevant to recovery.
- Remain read-only unless the user separately authorizes changes outside this analytical result.

## Native result requirements

1. **Subject, boundary, state or edition, receiving use, and resolved FPF source**
2. **Recovered entities, values, relations, and structure kinds**
3. **Current-state structure map or relation register**
4. **Evidence, inference labels, disputes, and missing information**
5. **Recovery stop and legal downstream handoff**

Do not present the recovered structure as a proposal, quality verdict, assurance result, or authorization.
