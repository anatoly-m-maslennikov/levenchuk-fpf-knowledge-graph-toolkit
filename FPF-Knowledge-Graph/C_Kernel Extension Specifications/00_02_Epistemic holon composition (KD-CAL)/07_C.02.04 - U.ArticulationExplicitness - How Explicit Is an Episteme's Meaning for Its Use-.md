**Plain-name.** Articulation explicitness.

**Use this pattern when.** Use [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]] when the next move depends on how explicitly a governed episteme's meaning is articulated for its semantic branch and receiving use.

**What goes wrong if missed.** A formal-looking sentence is treated as semantically ready, a real early cue is discarded as too vague, or every partly explicit note is forced through relation repair even when it is a plan, MethodDescription, Work claim, representation, question, characteristic, or ordinary domain statement.

**What this buys.** One branch-neutral ordinal characteristic: a stable cue can acquire recoverable governed structure and a complete form for its actual semantic branch, with meaning that remains stable in a receiving use, without confusing articulation with formality, closure, truth, trust, or endpoint authority.

## [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:1 - Problem frame
A governed `U.Episteme` can matter while its semantic shape is only partly explicit. The declared language-state chart over `U.CharacteristicSpace` therefore needs one basis-slot pattern for the degree to which that shape is explicitly articulated, without assuming in advance whether the direct branch is relational, planning, method, Work, representation, prompt, characteristic, or ordinary domain content.

## [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:2 - Problem
When articulation explicitness stays implicit, authors either overstate readiness for a receiving pattern or hide useful early structure. Reusing `F` for this judgement creates a category error: formality concerns rigor of expression, while articulation concerns whether the meaning needed by the actual receiving use is explicit. A relation-shaped ladder creates a second error by scoring other well-formed claim kinds as immature merely because they are not relations.

## [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:4 - Solution
`U.ArticulationExplicitness` is an ordinal characteristic of the degree to which a governed episteme's semantic structure is explicitly articulated for its branch and receiving use. It orders progression from a cue to a complete branch-appropriate expression whose meaning remains stable in a named receiving use. The common direction is independent of the semantic branch.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:4.0a - Kind and characteristic boundary

`U.ArticulationExplicitness` is a dependent durable characteristic value under the declared `U.LanguageStateSpace` / `U.CharacteristicSpace` boundary, not a root U-kind. Its identity is the articulation-explicitness basis slot and ordinal scale discipline for governed episteme publication positions. Local thresholds, route labels, and score-table columns may reference it, but they do not create a separate U-kind.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:4.1 - Characteristic specification
- **Kind:** CHR characteristic.
- **Scale discipline:** ordinal.
- **What rises:** semantic shape becomes more explicit.
- **What does not follow automatically:** truth, trust, closure, admissibility, or formality.

`AE` is therefore independent from `F`, from `LanguageStateClosureDegree`, and from endpoint authority.

Use [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/11_C.02.08 - U.ExtractableStructuralInformation - Structure This Reader Can Recover|C.2.8]] to compare how much selected structure a reader can correctly extract under stated preparation, access and budget, including when both expressions already meet the same `AE` threshold. Reader recovery supports an `AE` judgment about explicit articulation; it does not turn the `AE0`–`AE5` progression into a scale of extractable structural amount.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:4.2 - Starter anchor set
| Anchor | Reading | Typical admissible publication state |
|---|---|---|
| `AE0` | a cue is felt or observed but cannot yet be stated as a stable question or contrast | preserve the source or cue without claiming a route |
| `AE1` | a stable cue, question, contrast, or disturbance is nameable | an early cue publication becomes useful |
| `AE2` | candidate anchors, participants, actions, fields, or meanings are visible, but the branch or structure remains partial | route candidates and missing pieces can be stated |
| `AE3` | the governed claim structure is recoverable enough to choose its direct semantic branch | the relevant repair or authoring pattern may receive it if the local threshold is met |
| `AE4` | a complete branch-appropriate form is publishable with the participants, conditions, and bounds needed by the current use | the direct subject pattern can check or use the publication |
| `AE5` | the meaning remains stable in one named receiving use, and a later change can be reviewed without reconstructing it from the source | the receiving use is straightforward; the level alone does not settle truth, closure, trust, or use authorization |

The anchors are a starter set. A local use may refine them, but it shall keep the common direction and the distinction from `F` intact. A refined anchor may be branch-relative; it may not make relation structure the universal measure of articulation.

- **Formal-looking but semantically thin.** High `F`, low `AE`. Declare both.
- **Mystical cue immunity.** Low `AE` is presented as exempt from authoring discipline. Preserve it, but state what remains unresolved.
- **Ready-by-tone.** A sentence sounds precise, so authors assume `AE3+`. Publish the actual recoverable structure.
- **Relation-shaped shortcut.** Arrows, columns, or grammatical subjects and objects are treated as proof that the claim is relational. Recover the actual claim kind and route its branch before assigning the higher level.

To assign `AE`, ask:

- is a stable cue, question, or contrast nameable;
- which anchors, participants, actions, fields, or meanings are visible;
- is the direct semantic branch recoverable;
- is a complete form for that branch publishable;
- can the named receiving use interpret it without reconstructing the meaning from the source?

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:14.2 - Review prompt
A reviewer should reject an `AE` claim based only on rhetorical confidence or relation-shaped presentation. The claimed level should be supported by the branch-appropriate anchors, participants, actions, fields, meanings, conditions, bounds, or stable receiving-use structure.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:14.3 - Threshold publication reminder
If `AE` determines whether an episteme stays in [[A_Kernel Architecture Cluster/16_Language-State Moves- Choose the Next Publication and Use of a Cue or Claim/02_A.16.01 - PreArticulationCuePack- Preserve an Early Cue Before Choosing Its Use|A.16.1]], passes through [[B_Trans-disciplinary Reasoning Cluster/03_04_Coordinate Repeated Adaptation (Canonical Evolution Loop)/01_B.04.01 - Publish Candidate Routes for a Stabilized Cue (RoutedCueSet)|B.4.1]], or enters a direct receiving pattern, publish the local threshold and name that branch. Use [[A_Kernel Architecture Cluster/06_Signature Stack- Classify and Place Boundary Claims/10_P_Relational Precision Restoration - Recovering Direct Relations from Under-Specified Claims/00_A.06.P - Relational Precision Restoration - Recovering Direct Relations from Under-Specified Claims|A.6.P]] only for the relational branch; do not borrow its threshold for plans, methods, Work, representations, prompts, characteristics, or ordinary domain claims.

Contexts may refine the starter anchor set with subanchors, but the refinement must preserve the ordinal direction and the distinction from `F` and `CD`.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:15.2 - Migration from vague articulation prose
When routing or use depends on articulation, statements such as "still vague", "more explicit now", or "ready for formalization" should be migrated into explicit `AE` claims plus the corresponding move or routing claim.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:15.3 - Boundary reminder
`AE` does not govern closure, confidence, or warrant. If authors want those meanings, they must publish them through their own governing patterns.
## [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:16 - Articulation Publication Package Discipline

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:16.1 - Minimal articulation package
An `AE` claim that changes routing or use should be published with more than a level token. State:

- the exact episteme publication being judged;
- the stable cue, question, or contrast;
- the candidate anchors, participants, actions, fields, or meanings relevant to the current branch;
- the branch-appropriate structure already recoverable and any decision-relevant gap;
- the grounds for the level;
- the named next use and its local threshold when the level is used to change route.

Unresolved claim-bearing `role` wording goes first to [[E_The FPF Constitution and Authoring Guides/09_10_Unified Lexical Rules for FPF/06_E.10.ROLE - Recovering What “Role” Means in the Current Claim|E.10.ROLE]]. A bare `AE3` label is insufficient when the supporting structure and intended receiving branch are absent.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:16.2 - Threshold package for route change
When `AE` controls a route change, publish the intended receiving pattern, its semantic branch, the minimum recoverable structure it requires, and the current evidence that the publication meets or misses that threshold. A relational route may name [[A_Kernel Architecture Cluster/06_Signature Stack- Classify and Place Boundary Claims/10_P_Relational Precision Restoration - Recovering Direct Relations from Under-Specified Claims/00_A.06.P - Relational Precision Restoration - Recovering Direct Relations from Under-Specified Claims|A.6.P]]; another branch names its own receiving pattern.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:16.3 - Evidence-limited rise rule
`AE` may rise only as far as the published branch-appropriate structure—including any relevant anchors, slots, or contrasts—warrants. Stylistic polish, templates, or rhetorical confidence do not raise `AE` on their own.

## [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:17 - Threshold Crossing and Split Handling

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:17.1 - Branch-aware high-articulation exits
At `AE3+`, use the local threshold of the direct branch rather than one universal destination:

- for an actual relation claim, restore precision through [[A_Kernel Architecture Cluster/06_Signature Stack- Classify and Place Boundary Claims/10_P_Relational Precision Restoration - Recovering Direct Relations from Under-Specified Claims/00_A.06.P - Relational Precision Restoration - Recovering Direct Relations from Under-Specified Claims|A.6.P]] when needed, then use its direct relation pattern;
- for a plan or intended activity, use [[A_Kernel Architecture Cluster/15_System-Role-Method-Work Alignment/00_A.15 - System-Role-Method-Work Alignment|A.15]];
- for a Method, use [[A_Kernel Architecture Cluster/03_Transformer Quartet- Distinguish Work, Performer, Method and Method Description/01_U.Method- Reusable Way of Doing with Explicit Applicability/00_A.03.01 - U.Method- Reusable Way of Doing with Explicit Applicability|A.3.1]], while its MethodDescription remains an episteme under [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/01_C.02.01 - U.Episteme- Constitution, Empirical Grounding, and Edition Relations|C.2.1]];
- for a dated Work-occurrence claim, use [[A_Kernel Architecture Cluster/15_System-Role-Method-Work Alignment/01_A.15.01 - U.Work- Dated Performed Work Occurrence|A.15.1]] to test or recover admission;
- for a representation claim, use its direct subject pattern; use [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/02_P_Clarify Episteme, Publication, and Source Wording (Epistemic Precision Restoration)/01_C.02.P.DR - Repair Claims Based on Declarative Form Alone (Declarative Representation Precision Restoration)|C.2.P.DR]] when declarative form is being overread, adding [[A_Kernel Architecture Cluster/06_Signature Stack- Classify and Place Boundary Claims/08_03_Episteme viewing - EntityOfConcern-preserving episteme construction/03_RT_Representation-Scheme Transition- Change Representation of the Same EntityOfConcern/00_A.06.03.RT - Representation-Scheme Transition- Change Representation of the Same EntityOfConcern|A.6.3.RT]] only when a representation transition is current;
- for an abductive prompt or explicit open question, use [[B_Trans-disciplinary Reasoning Cluster/04_05_Choose the Next Reasoning Contribution (Canonical Reasoning Cycle)/12_02_Generate and Compare Candidate Explanations (Abductive Loop)/01_B.05.02.00 - Question Form for Entering Abduction (U.AbductivePrompt)|B.5.2.0]] or the direct question pattern;
- for a Characteristic or Scale claim, use [[A_Kernel Architecture Cluster/17_Canonical “Characteristic” (A.CHR-NORM)- Name What Is Measured/00_A.17 - Canonical “Characteristic” (A.CHR-NORM)- Name What Is Measured|A.17]] and [[A_Kernel Architecture Cluster/18_Minimal CSLC in Kernel (Characteristic ⟷ Scale ⟷ Level ⟷ Coordinate) (A.CSLC-KERNEL)/00_A.18 - Minimal CSLC in Kernel (Characteristic ⟷ Scale ⟷ Level ⟷ Coordinate) (A.CSLC-KERNEL)|A.18]], with [[C_Kernel Extension Specifications/04_16_Measurement & Metrics Characterization (MM-CHR)/04_C.16.P - Restore Precision to Characteristic and Scale Wording|C.16.P]] when its scalar wording hides the construction;
- for an ordinary domain claim, keep the episteme publication under [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/01_C.02.01 - U.Episteme- Constitution, Empirical Grounding, and Edition Relations|C.2.1]] and use the direct domain pattern that governs its subject.

If the branch or threshold is unresolved, keep the episteme in [[B_Trans-disciplinary Reasoning Cluster/03_04_Coordinate Repeated Adaptation (Canonical Evolution Loop)/01_B.04.01 - Publish Candidate Routes for a Stabilized Cue (RoutedCueSet)|B.4.1]] or [[A_Kernel Architecture Cluster/16_Language-State Moves- Choose the Next Publication and Use of a Cue or Claim/02_A.16.01 - PreArticulationCuePack- Preserve an Early Cue Before Choosing Its Use|A.16.1]] and state what is still missing. `AE` reports recoverable articulation; it does not itself choose the branch or authorize the receiving use.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:17.2 - High-articulation, low-closure cases
A note may reach `AE4+` while remaining low or mid in `CD`. In such cases state that articulation is sufficient for precise handling while closure still leaves rival routes or frames live.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:17.3 - Articulation claims for separate fragments
Scope each fragment's articulation claim to its receiving use; do not assign one averaged level that hides the actual route structure. The fragments may remain in the same note or publication when their scopes are clear.

## [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:18 - Review Matrix and Endpoint Boundary Tests

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:18.1 - Review matrix
A reviewer should ask:

- are the named anchors genuinely present rather than presupposed;
- does the level rest on recoverable meaning rather than tone, formatting, arrows, or columns;
- is the direct semantic branch explicit, or is a relation route being inferred from presentation alone;
- are the participants, actions, fields, meanings, conditions, bounds, or ordinary wording required by that branch still hidden;
- has an intended activity or plan been mislabeled as Tech `Work` before an occurrence is admitted;
- if `AE` justifies a route change, does the publication meet the named receiving pattern's entry conditions?

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:18.2 - Endpoint-boundary test
High `AE` does not by itself authorize endpoint claims, gate claims, or quality ascriptions. If such consequences appear, show which downstream governing pattern takes over.

### [[C_Kernel Extension Specifications/00_02_Epistemic holon composition (KD-CAL)/07_C.02.04 - U.ArticulationExplicitness - How Explicit Is an Episteme's Meaning for Its Use-|C.2.4]]:18.3 - Migration note for false precision
Rigid templates, capitalized labels, or tidy sentence rhythm can simulate articulation. Migration should therefore test whether the claimed branch-appropriate structure, including any required anchors or slots, is really recoverable; if not, the articulation level should drop.
